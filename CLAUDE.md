# Правила для сайтов

- Стек по умолчанию: Astro, статическая генерация. Next.js только если нужен бэкенд/авторизация.
- Каждая страница: уникальные title (до 60 символов вместе с суффиксом « — «Хвоя»», который добавляет BaseLayout; на главной суффикса нет) и description (140–160 символов), Open Graph с картинкой 1200×630.
- Ровно один H1 на странице, заголовки не перепрыгивают уровни. Заголовки по смыслу, не для размера шрифта.
- URL латиницей, через дефис, со слэшем на конце.
- sitemap.xml (@astrojs/sitemap) и robots.txt обязательно.
- JSON-LD: LodgingBusiness на главной и в контактах, BreadcrumbList на внутренних.
- Картинки через astro:assets, WebP, у всех alt.
- Коммерческие факторы: телефон, полный адрес, email, ИНН/ОГРН в подвале.
- Минимум клиентского JS. Перед завершением запускай npm run build и проверяй HTML в dist/.

## Специфика проекта: гостевой дом «Хвоя», с. Чертовицы (30 минут от Воронежа)
- Бизнес: аренда коттеджа целиком (до 10 гостей), свадьбы и праздники в шатре (до 70 гостей). Основной поисковик — Яндекс.
- Дизайн, тексты и фото брать из `_materials/` (прототип v4), не изобретать новый. `_materials/` — только эталон, не редактировать.
- Schema.org: `LodgingBusiness` на главной и в контактах, `House`/`Accommodation` на странице коттеджа, `EventVenue` на свадьбах и праздниках, `FAQPage` везде, где есть Faq, `ImageGallery` на фото, `Offer` на ценах.
- Рейтинг и отзывы (`AggregateRating`, `Review`) в разметку — только реальные, с Яндекс Карт. Не выдумывать.
- Факты (цены, телефоны, адрес, условия, FAQ) — один источник в `src/data/`, не хардкодить в страницах. Значения в [квадратных скобках] — уточнить у заказчика, на продакшен с ними не выходить.
- Цены писать с `&nbsp;` (`40&nbsp;000&nbsp;₽`), неразрывные пробелы после коротких слов в заголовках — как в прототипе.
- Сторонние виджеты (бронирование TravelLine/Bnovo, Яндекс Карта, отзывы) грузить лениво, после взаимодействия или при появлении в зоне видимости. Они не должны ломать LCP/CLS.
- Формы собирают персональные данные → хостинг в РФ (152-ФЗ), согласие со ссылкой на `/politika-konfidencialnosti/`.
- Политика и правила проживания (PDF) лежат на нашем домене, а не ссылками на старый сайт.
- После каждого этапа делать git-коммит.
- Внутренние ссылки писать через `href('/путь/')` из `src/lib/url.ts`, а не строкой `'/путь/'`: демо на GitHub Pages собирается в подпапку `/имя-репозитория/` (workflow `.github/workflows/deploy.yml`, закрыто от индексации).
