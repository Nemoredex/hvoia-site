# План сайта на Astro: гостевой дом «Хвоя» — техническое SEO

## Контекст

В `_materials/` лежит HTML-прототип v4: 7 страниц, `style.css`, `main.js`, фото в WebP и `data/hvoia.json` (компания, цены, дом, территория, свадьбы, праздники, FAQ). Компоненты размечены комментариями `COMPONENT:`. Формы шлют POST на `/api/lead`, который пока не существует. Проверка дат — демо, её нужно подключить к модулю бронирования.

План охватывает только техническую часть SEO: индексацию, мета-теги, микроразметку, картинки, скорость, переезд и запуск. Семантика, тексты и новые посадочные страницы сюда не входят.

Что нашлось при разборе прототипа:
- **Title длиннее 60 символов** на двух страницах: `kottedzh.html` — 63, `prazdniki.html` — 65.
- **Description короче 140 символов** на четырёх страницах: `foto.html` — 109, `kontakty.html` — 130, `kottedzh.html` — 135, `prazdniki.html` — 139.
- **Нет canonical** (закомментирован), `og:image`, `og:url`, `og:type`, favicon.
- **Неполный JSON-LD `LodgingBusiness`**: нет `url`, `geo`, `image`, `openingHours`, второго телефона. `FAQPage` вписан в HTML вручную, `BreadcrumbList` и видимых хлебных крошек нет.
- **Нет ОГРН** ни в подвале, ни в данных. ИНН есть.
- **Старый сайт `www.hvoia-event.ru`** (Drupal: пути `/policy`, `/sites/default/files/...`) ещё работает, на него ссылаются политика и PDF с правилами. При запуске нужны 301-редиректы, иначе потеряем накопленные позиции.
- **FAQ главной и цен не лежат в `hvoia.json`.** Они есть только в HTML, а цены продублированы по страницам.
- **Шрифты грузятся с Google Fonts** — внешний запрос блокирует отрисовку.
- **Заголовки:** заглушка `<h3>[Танцпол, свет, звук]</h3>` на свадьбах. Колонки подвала оформлены как `<h3>`, хотя по смыслу это не заголовки.
- **Схема маршрута** (`Route`) подключает шишку через `<image href>` в SVG, то есть мимо `astro:assets`.
- **Отзывы на странице «Фото»** — заглушка под виджет Яндекс Карт.

### Этап 4. Картинки — готово 20.11.2026
Итог: все фото через `astro:assets` (WebP), у каждой страницы своя OG-картинка 1200×630 из героя. Фото первого экрана: ширины 640–2560, качество 72 — на 1440 px вес LCP-картинки упал на 30–45% (свадьбы 627 → 372 КБ, контакты 551 → 310 КБ). Контентные фото — качество 75, декор-ветка — вариант 300 px (130 → 51 КБ). Preload LCP не нужен: `<img>` в начале HTML, preload-сканер находит его сам, а при арт-дирекции preload скачал бы оба кадра. AVIF не включали — правило проекта WebP.

1. Фото — в `src/assets/img/`, вывод через `<Image />` и `<Picture />`. Исходник — самый большой файл (2528/2560 px), ширины 1280/1920/2560 генерирует Astro, `sizes="100vw"` для героев.
2. Главная: арт-дирекция ПК/телефон (горизонтальный и вертикальный кадр) через `getImage()` и `<picture>` с `<source media>`.
3. LCP-картинка героя: `loading="eager"`, `fetchpriority="high"`, `<link rel="preload">` в `<head>`. Остальные — `loading="lazy"`.
4. У каждой картинки `width/height` (Astro проставит сам) и осмысленный alt из данных. Декор (ветка, шишки, полосы леса) — `alt=""` и `aria-hidden`, либо в CSS-фон.
5. Шишка в SVG `Route` — URL через `import pinecone from '...?url'` или `getImage()`.
6. OG-картинки 1200×630 для каждой страницы — из героев, через `getImage()`.

### Этап 6. Индексация — готово 20.11.2026
Итог: `src/pages/robots.txt.ts` — домен и Sitemap из конфига, в демо `Disallow: /`. Sitemap — 8 страниц, 404 исключена автоматически. `lastmod` не ставим: дата сборки на всех страницах одинаковая и ничего не говорит поисковику — честный `lastmod` появится вместе с CMS. 2. `public/robots.txt`:

   Allow: /
   Disallow: /api/

### Этап 7. Формы, бронирование, внешние виджеты
1. `@astrojs/node` только для `src/pages/api/lead.ts` (`prerender = false`): заявка уходит в Telegram и на почту, секреты в `.env`.

### Этап 8. Скорость (Core Web Vitals)
1. Шрифты — self-host через `@fontsource/prata` и `@fontsource/onest` (или `-variable`), только кириллица и латиница, `font-display: swap`, preload шрифта H1.
2. `main.js` разбить по компонентам: меню → `Header`, фильтр → `PhotoGallery`, формы → `LeadForm`, даты → `BookForm`. На страницах без этих блоков JS нет.
3. Критичные стили инлайнит Astro. Сторонние скрипты — только по событию.
4. Цели на мобильном (PageSpeed Insights, Lighthouse): LCP < 2,5 с, CLS < 0,1, INP < 200 мс, Lighthouse SEO и Performance ≥ 90.

### Этап 11. Автопроверка `dist/`
Скрипт `scripts/seo-check.mjs` (запуск после `npm run build`) обходит все HTML в `dist/` и падает с ошибкой, если:
- H1 не ровно один, или уровни заголовков перепрыгивают;
- title > 60 символов, description вне диапазона 140–160, title или description повторяются;
- нет canonical, `og:image`, `lang`;
- JSON-LD не парсится или на внутренней странице нет `BreadcrumbList`;
- у `<img>` нет атрибута `alt`, `width` или `height`;
