# План сайта на Astro: гостевой дом «Хвоя» — техническое SEO

## Контекст

В `_materials/` лежит HTML-прототип v4: 7 страниц, `style.css`, `main.js`, фото в WebP и `data/hvoia.json` (компания, цены, дом, территория, свадьбы, праздники, FAQ). Компоненты размечены комментариями `COMPONENT:`. Формы шлют POST на `/api/lead`, который пока не существует. Проверка дат — демо, её нужно подключить к модулю бронирования.

План охватывает только техническую часть SEO: индексацию, мета-теги, микроразметку, картинки, скорость, переезд и запуск. Семантика, тексты и новые посадочные страницы сюда не входят.

Что нашлось при разборе прототипа:
- **Title длиннее 60 символов** на двух страницах: `kottedzh.html` — 63, `prazdniki.html` — 65.
- **Description короче 140 символов** на четырёх страницах: `foto.html` — 109, `kontakty.html` — 130, `kottedzh.html` — 135, `prazdniki.html` — 139.
- **Нет canonical** (закомментирован), `og:image`, `og:url`, `og:type`, favicon.
- **Неполный JSON-LD `LodgingBusiness`**: нет `url`, `geo`, `image`, `openingHours`, второго телефона. `FAQPage` вписан в HTML вручную, `BreadcrumbList` и видимых хлебных крошек нет.
- **Нет ОГРН** ни в подвале, ни в данных. ИНН есть.
- **Старый сайт `www.hvoia-event.ru`** (Drupal: пути `/policy`, `/sites/default/files/...`) ещё работает, на него ссылаются политика и PDF с правилами. При запуске нужны 301-редиректы, иначе потеряем накопленные позиции.
- **FAQ главной и цен не лежат в `hvoia.json`.** Они есть только в HTML, а цены продублированы по страницам.
- **Шрифты грузятся с Google Fonts** — внешний запрос блокирует отрисовку.
- **Заголовки:** заглушка `<h3>[Танцпол, свет, звук]</h3>` на свадьбах. Колонки подвала оформлены как `<h3>`, хотя по смыслу это не заголовки.
- **Схема маршрута** (`Route`) подключает шишку через `<image href>` в SVG, то есть мимо `astro:assets`.
- **Отзывы на странице «Фото»** — заглушка под виджет Яндекс Карт.

## 2. Этапы

После каждого этапа — `npm run build`, проверка `dist/` и git-коммит.

### Этап 0. Подготовка
1. `git init`, проект Astro (та же версия и набор пакетов, что в «Юристах»), `.gitignore` по образцу.
2. Прототип в `_materials/` — эталон, не редактируется.
3. Главное зеркало — `https://www.hvoia-event.ru/`: старый сайт уже отдаёт 301 с `http://` и без `www` на него (проверено 19.11.2026). Оставляем его же — смена зеркала не нужна.
4. Выгрузить все URL старого сайта: его `sitemap.xml`, «Страницы в поиске» в Яндекс Вебмастере, внешние ссылки. Сохранить в `_migration/old-urls.csv` — это основа карты редиректов на этапе 9. Сделано по sitemap и открытым страницам; Вебмастер — когда заказчик даст доступ.
5. Снять текущие позиции и трафик (Вебмастер, Метрика), чтобы после переезда было с чем сравнить.

### Этап 1. Конфиг и SEO-каркас
1. `astro.config.mjs`: `site` — боевой домен, `base` из env для демо, `trailingSlash: 'always'`, `build.format: 'directory'`, интеграция `@astrojs/sitemap`.
2. `src/lib/url.ts` — `href()` для внутренних ссылок, как в «Юристах».
3. `src/layouts/BaseLayout.astro`, пропсы `title`, `description`, `h1?`, `jsonLd?`, `noindex?`, `ogImage?`, `crumbs?`. Внутри компонент `SeoHead`:
   - `<html lang="ru">`, `title` с суффиксом, `description`;
   - `<link rel="canonical">` на саму себя, абсолютный, со слэшем;
   - OG: `og:type`, `og:url`, `og:title`, `og:description`, `og:image` 1200×630, `og:locale=ru_RU`, `og:site_name`;
   - `meta robots`: `noindex, nofollow` при `noindex` или при `PUBLIC_NOINDEX=true` (демо);
   - favicon (svg + ico + apple-touch-icon), `site.webmanifest`, `theme-color`.
4. Проверка на этапе сборки: если title длиннее 60 символов или description вне диапазона 140–160, вывести предупреждение в консоль.

### Этап 2. Данные — один источник
`_materials/data/hvoia.json` разбить на:

| Файл | Что внутри |
|---|---|
| `src/data/company.json` | название, юрлицо, ИНН, **ОГРН [уточнить]**, адрес по частям (для JSON-LD), координаты **[уточнить]**, телефоны (текст + href), мессенджеры, email, часы, ссылка на Яндекс Карты, время заезда и выезда |
| `src/data/stay.json` | цены, доп. гости, залог, что входит, дом, территория |
| `src/data/events.json` | свадьбы (что входит, шаги), праздники (форматы, что входит), вместимость шатра |
| `src/data/faq.json` | `home`, `stay`, `wedding`, `prices` — включая FAQ главной и цен, которых сейчас нет в JSON |
| `src/data/gallery.ts` | импорт фото + категории фильтра (`house`, `territory`, `events`, `winter`) + alt |
| `src/data/navigation.ts` | меню и подвал |
| `src/data/seo.ts` | title, description и ogImage для каждой страницы |

Цены выводятся только из `stay.json`: в карточках, `/ceny/`, JSON-LD `priceRange` и `Offer`.

### Этап 3. Компоненты и страницы
1. Перенести блоки `COMPONENT:` из прототипа в `src/components/` один к одному. Стили — в `src/styles/global.css`, токены `:root` как есть.
2. Семантика заголовков:
   - один H1 — в `Hero` или `PageHero`;
   - колонки подвала — `<p class="site-footer__title">` вместо `<h3>`;
   - убрать заглушку `[Танцпол, свет, звук]` или заменить её реальными данными;
   - «Заявка отправлена» — заголовок того же уровня, что у формы, и только внутри блока успеха.
3. `Breadcrumbs` — видимые хлебные крошки в `PageHero` на внутренних страницах (в прототипе их нет, стиль взять из токенов) и JSON-LD `BreadcrumbList` из тех же данных.
4. `Faq` на `details/summary` — ответы есть в HTML сразу, без JS, поэтому поисковик их видит.
5. Ссылки: все внутренние через `href()`. Политика — `/politika-konfidencialnosti/`, PDF с правилами — `/docs/pravila-prozhivaniya.pdf` на нашем домене, оба ведут на свой сайт, а не на старый.
6. Ссылки на внешние сервисы (Яндекс Карты, Telegram, WhatsApp) — `rel="noopener"`, при открытии в новой вкладке.

### Этап 4. Картинки
1. Фото — в `src/assets/img/`, вывод через `<Image />` и `<Picture />`. Исходник — самый большой файл (2528/2560 px), ширины 1280/1920/2560 генерирует Astro, `sizes="100vw"` для героев.
2. Главная: арт-дирекция ПК/телефон (горизонтальный и вертикальный кадр) через `getImage()` и `<picture>` с `<source media>`.
3. LCP-картинка героя: `loading="eager"`, `fetchpriority="high"`, `<link rel="preload">` в `<head>`. Остальные — `loading="lazy"`.
4. У каждой картинки `width/height` (Astro проставит сам) и осмысленный alt из данных. Декор (ветка, шишки, полосы леса) — `alt=""` и `aria-hidden`, либо в CSS-фон.
5. Шишка в SVG `Route` — URL через `import pinecone from '...?url'` или `getImage()`.
6. OG-картинки 1200×630 для каждой страницы — из героев, через `getImage()`.

### Этап 5. Микроразметка (`src/lib/schema.ts`)
| Страница | Типы |
|---|---|
| Главная | `LodgingBusiness`: `name`, `url`, `logo`, `image[]`, оба `telephone`, `email`, `address`, `geo`, `openingHoursSpecification`, `checkinTime` 15:00, `checkoutTime` 12:00, `priceRange`, `amenityFeature` (бассейн, баня, чан, мангал, кондиционеры), `petsAllowed` [уточнить], `hasMap`, `sameAs` (Яндекс Карты, Telegram) + `FAQPage` |
| Коттедж | `House` (или `Accommodation`): `floorSize` 170 м², `numberOfRooms` 4, `numberOfBathroomsTotal` 2, `occupancy` до 10, `containedInPlace` → `LodgingBusiness` + `FAQPage` + `BreadcrumbList` |
| Свадьбы, Праздники | `EventVenue`: `maximumAttendeeCapacity` 70 + `FAQPage` (свадьбы) + `BreadcrumbList` |
| Цены | `Offer` / `OfferCatalog` с ценами из `stay.json` + `FAQPage` + `BreadcrumbList` |
| Фото | `ImageGallery` + `BreadcrumbList` |
| Контакты | `LodgingBusiness` (тот же генератор) + `BreadcrumbList` |

Правила:
- Один `@id` у организации (`https://домен/#org`), остальные типы ссылаются на него.
- Текст в `FAQPage` совпадает с видимым на странице — берётся из того же `faq.json`.
- `AggregateRating` — только когда будут реальные данные с Яндекс Карт.
- Проверка: валидатор микроразметки Яндекса и validator.schema.org.

### Этап 6. Индексация
1. `sitemap-index.xml` из `@astrojs/sitemap`: 404 исключить, `lastmod` по дате сборки.
2. `public/robots.txt`:
   ```
   User-agent: *
   Allow: /
   Disallow: /api/
   Clean-param: utm_source&utm_medium&utm_campaign&utm_content&utm_term&yclid&gclid&from

   Sitemap: https://<домен>/sitemap-index.xml
   ```
   Для демо на GitHub Pages — `Disallow: /` плюс `noindex` в мета (через `PUBLIC_NOINDEX`).
3. `404.astro` — `noindex`, хостинг отдаёт настоящий код 404, а не 200.
4. Одна версия каждого URL: со слэшем, без `index.html`, один протокол и одно зеркало. Остальное — 301 на хостинге.

### Этап 7. Формы, бронирование, внешние виджеты
1. `@astrojs/node` только для `src/pages/api/lead.ts` (`prerender = false`): заявка уходит в Telegram и на почту, секреты в `.env`.
2. Защита от спама: honeypot + Яндекс SmartCaptcha. Чекбокс согласия со ссылкой на политику.
3. Модуль бронирования (TravelLine / Bnovo — выбрать с заказчиком) грузится только после клика по «Проверить свободные даты». Если модуль открывает свои страницы на нашем домене — закрыть их от индексации, чтобы не плодить дубли.
4. Яндекс Карта и виджет отзывов — лениво, через `IntersectionObserver`, с заглушкой фиксированного размера (без CLS).
5. Метрика: цели на отправку заявки, клик по телефону и мессенджерам, открытие бронирования. Счётчик подключать с `defer`.

### Этап 8. Скорость (Core Web Vitals)
1. Шрифты — self-host через `@fontsource/prata` и `@fontsource/onest` (или `-variable`), только кириллица и латиница, `font-display: swap`, preload шрифта H1.
2. `main.js` разбить по компонентам: меню → `Header`, фильтр → `PhotoGallery`, формы → `LeadForm`, даты → `BookForm`. На страницах без этих блоков JS нет.
3. Критичные стили инлайнит Astro. Сторонние скрипты — только по событию.
4. Цели на мобильном (PageSpeed Insights, Lighthouse): LCP < 2,5 с, CLS < 0,1, INP < 200 мс, Lighthouse SEO и Performance ≥ 90.

### Этап 9. Переезд со старого сайта
1. Карта редиректов `_migration/redirects.csv` (старый URL → новый) на основе этапа 0. Минимум: `/policy` → `/politika-konfidencialnosti/`, путь к PDF правил → `/docs/pravila-prozhivaniya.pdf`, страницы услуг Drupal → соответствующие новые страницы, остальное → ближайшая по смыслу страница (не всё подряд на главную).
2. 301 — на уровне сервера (nginx или `.htaccess`, смотря по хостингу), без цепочек.
3. Если меняется зеркало или домен — «Переезд сайта» в Яндекс Вебмастере и смена адреса в Google Search Console.
4. Первые две недели после запуска следить за ошибками 404 и выпадением страниц в Вебмастере.

### Этап 10. Хостинг и запуск
1. Хостинг в РФ (Timeweb, Beget, Selectel): HTTPS, HTTP/2, сжатие brotli/gzip, `Cache-Control: immutable` для `/_astro/*`.
2. Яндекс Вебмастер: подтвердить права, добавить sitemap, проверить ответ сервера и robots.txt, переобход ключевых страниц, IndexNow.
3. Регион — Воронеж: через карточку в Яндекс Бизнесе (организация 200587327520). URL сайта в карточке — новый, адрес и телефоны совпадают с сайтом символ в символ.
4. Google Search Console: подтверждение, sitemap.
5. Демо на GitHub Pages — по образцу «Юристов» (`deploy.yml`, `PUBLIC_NOINDEX=true`), закрыто от индексации.

### Этап 11. Автопроверка `dist/`
Скрипт `scripts/seo-check.mjs` (запуск после `npm run build`) обходит все HTML в `dist/` и падает с ошибкой, если:
- H1 не ровно один, или уровни заголовков перепрыгивают;
- title > 60 символов, description вне диапазона 140–160, title или description повторяются;
- нет canonical, `og:image`, `lang`;
- JSON-LD не парсится или на внутренней странице нет `BreadcrumbList`;
- у `<img>` нет атрибута `alt`, `width` или `height`;
- в тексте остались `[квадратные скобки]` (незакрытые вопросы к заказчику);
- внутренняя ссылка ведёт на несуществующую страницу или без слэша на конце;
- страница из `dist/` отсутствует в sitemap (кроме 404).

## 3. Что нужно от заказчика (для технической части)
Решение по зеркалу (с `www` или без), доступы к DNS, хостингу и Вебмастеру/Метрике старого сайта, ОГРН, координаты, выбор модуля бронирования, текст политики ПДн, PDF правил проживания, токен Telegram-бота и почта для заявок, отзывы и рейтинг для виджета.

## Проверка плана
- Все 7 страниц прототипа есть в таблице, URL совпадают с маршрутами из README прототипа.
- Каждое поле `hvoia.json` нашло место в `src/data/`.
- Каждый блок `COMPONENT:` из прототипа переносится в компонент.
- Каждая проблема из раздела «Что нашлось» закрывается одним из этапов: title и description — этапы 1 и 11; canonical и OG — этап 1; JSON-LD — этап 5; ОГРН — этап 2; старый сайт — этапы 0 и 9; шрифты — этап 8; заголовки — этап 3; SVG-шишка — этап 4.
